# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `list_employees` / line 93 | **Pagination off-by-one**: `skip = page * page_size` skips page 1 entirely. With page=1 and page_size=20, it skips 20 items instead of 0. | GET /employees?page=1 returns from the second page (items 21-40), and page 0 would be needed for the first page — but page starts at 1 per the spec. | Changed to `skip = (page - 1) * page_size`. |
| 2 | `list_employees` / line 94 | **`total` counts unfiltered**: `count_documents({})` always counts the entire collection, even when the `department` filter is applied. | GET /employees?department=Sales shows `total` equal to all employees, not just Sales. | Changed to `count_documents(q)` so `total` reflects the filter. |
| 3 | `list_employees` | **No sort order**: the spec requires results sorted by `emp_code` ascending, but the query has no `.sort()`. | Results come back in insertion order, which may not match `emp_code` order. | Added `.sort("emp_code", ASCENDING)`. |
| 4 | `punch_in` / line 102 | **Timezone-naive datetime**: `datetime.fromtimestamp(...)` creates a naive datetime (no timezone info). The data model requires BSON dates to be stored as UTC datetimes. | Stored datetimes are ambiguous; comparisons with tz-aware datetimes from seeded data would break. All analytics relying on IST conversion would be incorrect. | Used `datetime.fromtimestamp(ms / 1000, tz=timezone.utc)` and `truncate_to_seconds()`. |
| 5 | `punch_in` / line 101 | **No 404 for unknown employee**: If `emp_code` doesn't exist, `db.employees.find_one()` returns `None`, then `emp["shift_start"]` raises `TypeError`. The spec requires 404. | POST /attendance/punch-in with a non-existent emp_code causes a 500 Internal Server Error instead of 404. | Added explicit `if not emp: raise HTTPException(404, ...)` check. |
| 6 | `punch_in` / line 104 | **Race condition (check-then-insert)**: The code does `find_one` then `insert_one`, allowing two concurrent requests to both pass the check and both insert. Spec says exactly one 201, rest 409. | Under concurrent load, duplicate records for the same (emp_code, date) can be created. | Replaced with a unique compound index on `(emp_code, date)` and catching `DuplicateKeyError`. |
| 7 | `compute_late_minutes` / line 37 | **Wrong grace threshold**: `minutes > 10` is computed from `int((punch_in - start).total_seconds() / 60)`, which truncates differently than R2 specifies. R2 says strictly more than 10:00 (600 seconds) and then floor of total minutes. The existing code fails the edge case: 09:40:01 should give 10 minutes late, but `int(601/60) = 10`, and `10 > 10` is False, so it returns 0. | Punch-in at 09:40:01 for a 09:30 shift incorrectly reports 0 late minutes instead of 10. | Changed to compare raw seconds: `> 600` means late, then `int(seconds // 60)` for floor. |
| 8 | `compute_overtime` / line 46 | **Doesn't handle overnight shifts**: Uses `datetime.fromisoformat(date_str)` for shift_end but doesn't account for overnight shifts where shift_end falls on the next calendar day. | An overnight-shift employee (22:00-06:00) punching out at 06:40 the next day gets 0 overtime instead of 40 because `shift_end` is placed on the start day. | Created `compute_overtime_with_shift()` that checks if the shift is overnight and places `shift_end` on the correct calendar day. |
| 9 | `list_attendance` / line 144 | **Loads entire collection into memory**: `list(db.attendance_logs.find(q))` fetches all matching documents, then sorts and paginates in Python. The spec says "must stay fast on ~100k records; do not load the collection into memory." | With a large dataset, this endpoint would consume excessive memory and be slow. | Used MongoDB `.sort().skip().limit()` and `count_documents()` for server-side pagination. |
| 10 | `create_employee` / line 82 | **`created_at` is naive**: `datetime.now()` has no timezone info. Should use UTC for consistency with the data model. | Timestamps would be stored without timezone context, potentially causing issues when converting to epoch milliseconds in responses. | Changed to `datetime.now(timezone.utc)`. |
| 11 | `create_employee` / line 79 | **Race condition**: `find_one` then `insert_one` allows concurrent creates of the same emp_code. The spec says "enforced by a database unique index." | Two concurrent POST /employees with the same emp_code could both succeed, creating duplicates. | Removed the find_one check. Used `DuplicateKeyError` from the unique index to return 409. |
| 12 | `create_employee` / response | **`_id` not excluded, `created_at` not epoch ms**: The response includes raw datetime for `created_at` instead of epoch milliseconds, and doesn't formally exclude `_id` from the schema. | Response doesn't match the OpenAPI contract which specifies `created_at` as `EpochMillis`. | Used `format_employee()` to convert `created_at` to epoch ms and exclude `_id`. |
| 13 | `health` / line 73 | **Doesn't actually ping MongoDB**: The spec says "returns 200 only if MongoDB answers a ping, otherwise 503." The starter just returns ok without checking. | If MongoDB is down, /health still returns 200, breaking the readiness probe. | Added `client.admin.command("ping")` with a try/except that raises 503. |
| 14 | Entire file | **No indexes created at startup**: The spec says "create all indexes at startup, idempotently." | No indexes means COLLSCAN for all queries on large datasets, and no uniqueness enforcement at the DB level. | Added `@app.on_event("startup")` handler with all necessary indexes. |
| 15 | `punch_in` — attendance date | **Doesn't implement R1 for overnight shifts**: Uses `ts.date().isoformat()` which always uses the calendar date of the timestamp. For overnight shifts, a punch-in before `shift_end` should belong to the previous day. | An overnight-shift employee punching in at 23:30 gets date = today, but punching in at 05:00 should get date = yesterday (the day the shift started). Both get today's date. | Implemented `determine_attendance_date()` per R1. |
| 16 | `PunchInIn` model | **No validation on `punched_at`**: Accepts any integer including seconds-looking values (< 100000000000) and floats. The spec rejects these with 422. | Sending `punched_at: 1783312500` (seconds) or `punched_at: 1783312500000.5` (float) should return 422 but doesn't. | Added Pydantic validators per the EpochMillis schema. |

**Not a defect:**
- The `IST = timezone(timedelta(hours=5, minutes=30))` definition is correct. IST is a fixed UTC+05:30 offset, so using `timezone(timedelta(...))` is appropriate (no DST transitions).
- Using `pymongo.MongoClient` directly (not async Motor) is acceptable since FastAPI runs sync endpoints in a threadpool by default.
